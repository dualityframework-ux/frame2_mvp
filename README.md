frame² is a lightweight sports analytics and content engine built to explain games through **process vs result**.

the goal is simple:

**observe → detect the edge → explain the mechanism → generate insights**

## demo

example output generated by frame²:

observation  
2024 red sox finished 81-81.

mechanism  
run differential was neutral, but the offense relied heavily on duran as the lone consistent process driver.

implication  
the result and underlying process were aligned — an average team produced an average outcome.

## core ideas

most fans watch the scoreboard.

frame² tries to explain **why the scoreboard moved**.

the engine focuses on identifying hidden drivers such as:

- contact quality
- plate discipline
- run expectancy swings
- roster structure
- development pipeline

these signals help reveal the **mechanism behind outcomes**.

## Feature status

- **Available:** historical season analytics, franchise timelines, post generation,
  PDF and presentation exports.
- **Manual simulator:** the game page uses the values you enter; it is not a live feed.
- **Experimental:** the Statcast adapter; automated ingest and tilt agents are placeholders.

## roadmap

planned upgrades for frame²:

- live game ingestion
- automated tilt detection
- multi-sport support (nba / nfl / mlb)
- real-time insight generation
- integration with social publishing pipelines

## project structure

```
frame2_mvp/
├── app/
│   ├── app.py            # streamlit entry point
│   └── pages/            # dashboard pages (explorer, timeline, post generator, live game)
├── intelligence/         # signal / noise and process-vs-result logic
├── content_engine/       # insight → post generator
├── adapters/             # data loaders (history csv, mlb stats api)
├── agents/               # orchestrator that ties the engines together
├── config/               # settings, styles, utils
├── storage/parquet/      # red sox season data (1967–2024)
├── images/               # readme screenshots
├── tests/                # pytest suite
└── requirements.txt      # python dependencies
```

## run locally

```bash
git clone https://github.com/dualityframework-ux/frame2_mvp.git
cd frame2_mvp

pip install -r requirements.txt
PYTHONPATH=. streamlit run app/app.py
```

## tests

```bash
python -m pip install -r requirements-dev.txt
python -m compileall -q adapters agents app config content_engine intelligence memory models *.py
PYTHONPATH=. python -m pytest -q
```

The tests cover the adapters, settings, data integrity, the history and signal engines, the orchestrator and the post generator. github actions runs them on every push.
